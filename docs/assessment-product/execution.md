## Implementation and data decisions

- **AP-D1, AP-W02.** Forward schema version 4 adds optional assessment context and UUIDs for lineage, records and addressable relationships. Save As keeps the lineage. Uncommitted upgrades get fresh identities when the original file is opened again. A dependency route edit keeps the relation's UUID, while a deleted and recreated relation receives a fresh one. An unchanged update to the service aggregate keeps its relation IDs.
- **AP-D2, AP-W04 and AP-W06.** Focused outputs use the displayed map's records and route scope. They omit assessment-level details and reduce shared context to required fields. The full dataset marking and caveat apply throughout. Notes retain a marking at least as high as the dataset floor when saved. Typed JSON preserves exact values. Human CSV is a presentation format with formula protection.
- **AP-D4, AP-W03.** Schema version 5 persists current-layout viewpoints with typed UUID references and viewport framing. A restore with a missing subject, filter, or scenario is refused with an explicit repair path. The definition can be replaced with the currently displayed map. Reopening a live view reads current inventory and saved map positions.
- **AP-D5, AP-W06.** Schema version 6 retains questions and evidence when any linked target disappears. Review is tied to the stored assertion value, with pending review shown when that value changes. Annotations are separate, explicit repository commands.
- **AP-D3, AP-W07 and AP-W08.** Schema version 7 retains a bounded team-scoped issuance base. A native Save or reopening a downloaded file establishes readiness to export. The correction package uses typed set/clear proposals and compares those with fields in a trusted local issuance. Changes selected in the review are applied in one transaction. Suggestions outside supported fields require review in the existing editor.
- **AP-D6, AP-W05 and AP-W09.** The decision views derive recorded paths, distinct responsibility roles and logical dependency counts from inventory. A batch requires a fixed explicit selection and an inspected preview. Its accepted writes are atomic and preserve support notes and positions. Duplicate suggestions are informational and show recorded uses.

# Real-participant and native acceptance protocol

Prepared for execution; no participant sessions or native results are asserted here. Use fictional UNCLASSIFIED practice data only. Record the actual candidate filename/SHA-256, About identity, browser/version, OS, zoom and input/accessibility setup before starting. Obtain ordinary participant consent before observation. Do not collect operational inventory, identifying screenshots or invented ratings.

## Uncoached sessions

Recruit representative solutions engineers, inventory curators, architecture planners, keyboard/assistive-technology users and briefing owners. Use one facilitator and one observer when available. Give the task goal without naming controls or showing the expected route. Keep assistance separate from independent completion; record pauses, wrong turns, recovery, data errors and the participant's own explanation. Do not turn synthetic role hypotheses into participant quotations or success rates.

| Role | Goal | Observe |
| --- | --- | --- |
| Interview engineer | Record a service, discover a missing provider, interrupt and resume without losing notes. | Whether shared-child commit and parent Apply are understood; ability to recover from warnings. |
| Curator | Update ten service references, reuse qualified shared records, create one new organization and attach it twice. | Duplicate/wrong-network choices, current-assignment comprehension, paging and creation discoverability. |
| Planner | Compare two proposals, inspect a broken route, find the exact authored change and return to As-Is. | Baseline/projection distinction, direction, unsupported inference, return paths. |
| Keyboard/AT user | Edit, create inline, page results, inspect a connection and capture at 200%/400% zoom. | Focus order/visibility/return, spoken names/statuses/errors, scrolling burden and task parity. Conduct actual screen-reader testing separately. |
| Briefing owner | Deliver a boundary view and a detailed capture; explain scope, missing evidence, caveat and application identity. | Whether the viewer mistakes recorded connectivity for verified completeness; practical caption/detail readability. |

After each task ask the participant to explain what was saved, what remains pending and what the picture proves. Ask where they expected an action and what they would do next. Record actual observations before proposing solutions. Stop immediately for unexpected loss, wrong-record writes, misleading marking or inability to recover. Preserve a disposable reproduction and exact build identity; never repair evidence silently.

## Native file and recovery session

Use a new temporary directory with no personal files. Run both supported installed browsers on the exact candidate. Never disable enterprise controls. Each case needs an observed outcome and independent reopening/readback of the resulting `.sqlite`; screenshots of app status alone are insufficient.

1. Save a new synthetic dataset to a temporary file. Edit, Save again, reopen and compare content. Exercise Save As, then cancel Save As while retaining the current draft and current file association.
2. If the browser presents a permission prompt, test refusal and recovery with a disposable file. If no prompt appears, record denial as untested. Do not alter browser security policy to force a result.
3. Choose an optional recovery file, apply changes, wait for the explicit recovery result, reopen it and compare the latest applied state. Verify unapplied text is outside recovery, classification is preserved and Stop/Retry behave truthfully.
4. Test a cancelled recovery selection and a non-writable disposable target if safely available. Verify current document association and dirty state remain accurate.
5. With a separate disposable copy, modify the backing file externally and attempt Save. Verify conflict refusal, retained current draft and safe Save As. Reopen both files to establish which bytes changed. Do not use personal or operational files.
6. Exercise an actual close/reload warning after trusted child-only input; choose Stay, verify exact raw text, then explicitly cancel the child. Record prompt behavior separately from native file permissions.

File replacement during delayed reads/writes is adapter-tested automatically. A real native timing/conflict test needs an observable native setup and must not inherit an adapter pass. Keep unsupported/fallback behavior separate from a supported native branch.

Undo/redo, unsaved-changes guard and Find

Every repository write is one undoable step (via temporary triggers), the map restores saved positions after undo, New/Open/close warn before discarding edits, and Find on map focuses a node by name.

Approach

APP-1

Approach

Binding decision refs
  • DEC-1
  • DEC-2
  • DEC-3
ChoiceTemporary triggers on every table log reversing SQL into a temporary undo_log; one write is one step, with a History rule (own, merge into the write just before, none); replay runs a step newest-first with deferred foreign keys and logs its own reversal as the opposite step. The map moves every leaf to its saved position on refresh and places only nodes without one; a service that changes network loses its stale position. Main adds Undo/Redo buttons and keys, an unsaved-edits guard, and the editor rebuilds its form after undo/redo; the map toolbar gets Find on map.
TradeoffTriggers capture cascades and every table, including future ones, without per-method inverse code; temporary objects stay out of saved files because export copies only the main schema.

Sections

SEC-SMARTS

SMARTS design rationale

Blocks

Undo mechanism: whole-database snapshots per write (simple but replace the Database object and reset the view), per-method inverse code (misses cascades and every future table), or SQLite temporary triggers logging reversing SQL (captures cascades and new tables automatically, keeps the same connection, stays out of saved files because sql.js exports through the backup API). Temporary triggers chosen.

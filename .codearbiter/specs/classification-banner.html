Classification banner

A banner at the top and bottom of the app shows the highest marking in the dataset, colored by level, with an optional validated caveat stored in the dataset.

Banner rule and caveat

Authorityinherited
ChoiceHighest marking present (Q-013) plus an optional dataset caveat appended as MARKING//CAVEAT (Q-029).
RationaleQ-013 and Q-029 answered.
Source refSRC-DECOMP
DEC-2

Caveat characters

Authorityinherited
ChoiceQ-029 says free text; SIM narrows it to up to 80 upper-case letters, digits, spaces, commas, hyphens and slashes. With no dots or colons a caveat cannot hold an IP or host name, and no Save anyway path is needed.
RationaleBanner caveats use only these characters; the narrowing enforces CON-001 by construction.
Source refSRC-SEC
DEC-3

Colors

Authorityinherited
ChoiceUNCLASSIFIED #007A33, CUI #502B85, CONFIDENTIAL #0033A0, SECRET #C8102E (Astro design system, based on the SF-70x label Pantone colors and SF-902 for CUI); TOP SECRET #FF671F (SF-706 orange) with black text for contrast.
RationaleNo palette was stated in the project; these are the published conventions (astrouxds.com classification markings; SF-706 value in fcaviggia/classification-banner).

Sections

SEC-SMARTS

SMARTS design rationale

Blocks

Caveat storage: meta table versus a migration adding a column. The meta table needs no schema change but has no constraints, so validation runs on write and on open (a crafted caveat could otherwise show misleading banner text). Untrusted stored caveats: refuse the file or show the marking alone with a warning; refusing matches how other altered rows are handled.

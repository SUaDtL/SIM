Hand-entry UI

Side-panel data entry: a collapsible entity list on the left, a reserved map region in the center and an editor on the right, covering every entity and relationship through the repository.

Approach

APP-1

Approach

Binding decision refs
  • DEC-1
  • DEC-2
ChoicePlain DOM modules (no framework): a pure form model per entity type (fields, form values to repository input, error field to input), a list panel, an editor panel with per-row relationship writes, and main.ts wiring that rebuilds the repository on New/Open. CSS is imported and inlined by the build.
TradeoffHand-built DOM is more code than a framework but adds no dependency and stays within the lint bans (no innerHTML).

DEC-2

Relationship writes

Authorityinherited
ChoiceEach relationship row change is its own repository write; entity Save covers only the entity's own fields.
RationaleSeparate repository calls cannot be bundled atomically; per-row writes avoid half-applied saves.

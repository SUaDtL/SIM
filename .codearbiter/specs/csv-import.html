CSV import

Import networks, organizations, categories, applications, services, CDS, support tiers, consumers and dependencies from CSV files, one per template, with a preview of what will be added, skipped and refused, as one undo step.

Approach

APP-1

Approach

Binding decision refs
  • DEC-1
  • DEC-2
  • DEC-3
ChoiceA strict UTF-8 RFC 4180 parser with size caps; one template per entity or relationship matched by its exact column set; an engine that writes every row through the repository inside repository.group(), skipping records that already exist; the preview runs the same engine on a throwaway copy of the dataset. A bulk addition re-lays out the whole map.
TradeoffExact headers refuse a misspelled column instead of guessing; skipping existing records never overwrites a user's edits, at the cost of no update-by-import.

Decisions

DEC-1

Existing records

Authorityinherited
ChoiceA row naming a record that already exists (case-insensitive; services by name and network) is reported and left unchanged; a support tier held by a different organization is refused, not replaced.
RationaleAn import never overwrites edits made in SIM.
Source refSRC-DECOMP
DEC-2

Values

Authorityinherited
ChoiceFoundational blank takes the Identity/DNS default; yes/y/true/1 and no/n/false/0 are accepted; markings match case-insensitively; organization parents are set in a second pass so order within the file does not matter; files are applied in template order whatever order they were chosen in.
RationaleSpreadsheets are filled in loosely; the import accepts what is unambiguous.
Source refSRC-DECOMP
DEC-3

Undo and layout

Authorityinherited
ChoiceOne import is one undo step that never merges into the edit before it; when the new nodes are more than half of the map, the whole map is laid out again and the positions join the import's step.
RationalePlacing many nodes around a few pinned ones crowds them.
Source refSRC-DECOMP

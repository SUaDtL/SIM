Dataset schema, migrations and open/save

Versioned SQLite schema v1 for SIM's MVP entities, a forward-only migration runner, validated opening of untrusted .sqlite files, and New/Open/Save/Save As using the File System Access API with a download/upload fallback.

Scope

StatementSchema v1 tables: meta (name, caveat, created_at), network (kind internal|external, marking), organization (optional parent), category, application, service (network, application, category, provider org, marking, foundational flag), support_assignment (tier 1-3), cds, cds_network, org_consumes, service_dependency (optional via CDS).

Approach

APP-1

Approach

Binding decision refs
  • DEC-1
  • DEC-2
  • DEC-3
  • DEC-4
ChoicePlain SQL schema in TypeScript migration modules under src/db/migrations, applied by a runner keyed on PRAGMA user_version inside a transaction; PRAGMA application_id identifies SIM files; INTEGER primary keys; foreign keys enforced per connection; a DatasetFile service wraps the File System Access API with download/upload fallback. Only one sane approach exists given ADR-0001.
TradeoffRaw SQL migrations instead of an ORM keep the bundle small and offline-safe, at the cost of writing SQL by hand.

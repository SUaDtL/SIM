SEC-SMARTS

SMARTS design rationale

Blocks

SMARTS: no material unresolved solution choice under the fixed offline single-file, repository-only writes and saved-position constraints. Embed generated runtime notices in the one deliverable; use shared detector and size bound; paginate diagnostics in memory and download complete safe receipts; keep geometry changes render-only with bounded obstacle avoidance and proportional annotations. Scalable: bounded lists/routes at the declared roughly100-service estate. Maintainable: existing DOM, repository and capture interfaces reused. Available: offline controls and fail-closed missing notices. Reliable: original bytes, draft, endpoints and session ownership retained. Testable: regression-first source-specific tests and actual export inspection. Securable: existing CSP, size/sensitive checks, classification and safe text/CSV remain operative. Real participant and physical file durability evidence remain unknown and do not certify release. Implementation methods are reversible and within the user-authorized thirteen findings.
